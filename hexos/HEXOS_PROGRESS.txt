1. VISION GENERAL
================================================================================

HEXOS es el kernel ejecutivo del sistema HELIOS. Su funcion es:
- Gestionar recursos de hardware (GPU, RAM, CPU)
- Proporcionar telemetria en tiempo real
- Coordinar modulos cognitivos via IPC
- Reservar y administrar memoria VRAM/RAM

HEXOS NO ejecuta inferencia directamente - es el "cuerpo" que protege
y coordina los modulos cognitivos (Cognitive Kernel, Memory Core, etc).

------------------------------------------------------------------------------
3.1 BOOT SEQUENCE (6 FASES)
------------------------------------------------------------------------------
Estado: IMPLEMENTADO Y FUNCIONAL

Fase 1 - Hardware Detection:
  - Deteccion CPU: vendor, modelo, cores, frecuencia, cache, AVX2/AVX512
  - Deteccion RAM: total, disponible, tipo DDR4/DDR5
  - Deteccion Storage: tipo (HDD/SSD/NVMe), espacio libre
  - Deteccion GPU: via NVML (libnvidia-ml.so)
    * Nombre, driver version
    * VRAM total/libre
    * Compute capability
    * SM count, CUDA cores, Tensor cores
    * PCIe gen/width/bandwidth
    * Power limit, temp limit
    * Caracteristicas: FP16, BF16, INT8, TF32

Fase 2 - Hardware Contract:
  - Genera contract_id unico (hash del hardware)
  - Sella contrato (inmutable post-boot)
  - Muestra resumen del sistema

Fase 3 - Module Attestation:
  - Verifica integridad de modulos (demo - lista fija)
  - Modulos: hnf_loader, memory_core, cognitive_kernel, predictive_mem

Fase 4 - Resource Allocation:
  - Calcula VRAM budget segun perfil:
    * BALANCED: 60% model, 30% KV, 8% workspace, 2% reserve
    * LOW_VRAM: 70% model, 20% KV, 8% workspace, 2% reserve
    * PERFORMANCE: 55% model, 35% KV, 8% workspace, 2% reserve
  - Muestra barra visual del budget

Fase 5 - Runtime Initialization:
  - Inicializa IPC Bus (REAL - shared memory)
  - CUDA Memory Pools (DEMO - no cudaMalloc real)
  - Prepara interfaz Cognitive Kernel

Fase 6 - HELIOS Activation:
  - Muestra mensaje CONTINUITY (via IPC si disponible)
  - Estado de modulos cognitivos

3.2 DETECCION DE HARDWARE
------------------------------------------------------------------------------
Estado: IMPLEMENTADO Y FUNCIONAL (100% REAL)

CPU (src/hw/cpu.c):
  - Lee /proc/cpuinfo
  - Detecta vendor (Intel/AMD)
  - Cuenta cores fisicos/logicos
  - Lee frecuencias base/max
  - Detecta AVX2, AVX512, AMX

RAM (src/hw/ram.c):
  - Lee /proc/meminfo
  - Total, disponible, buffers, cached
  - Calcula usable y spillover_max

Storage (src/hw/storage.c):
  - Usa statvfs() para espacio libre
  - Detecta tipo via /sys/block/*/queue/rotational
  - Clasifica: HDD, SSD, NVMe

GPU (src/hw/gpu_nvml.c):
  - Carga dinamica de libnvidia-ml.so (dlopen)
  - No requiere CUDA SDK instalado
  - Funciones NVML usadas:
    * nvmlInit_v2
    * nvmlDeviceGetCount_v2
    * nvmlDeviceGetHandleByIndex_v2
    * nvmlDeviceGetName
    * nvmlDeviceGetMemoryInfo
    * nvmlDeviceGetCudaComputeCapability
    * nvmlDeviceGetNumGpuCores
    * nvmlDeviceGetPciInfo_v3
    * nvmlDeviceGetPowerManagementLimit
    * nvmlDeviceGetTemperatureThreshold
    * nvmlSystemGetDriverVersion
  - Fallback simulado si NVML no disponible

3.3 TELEMETRIA EN TIEMPO REAL
------------------------------------------------------------------------------
Estado: IMPLEMENTADO Y FUNCIONAL (100% REAL)

Arquitectura:
  - Thread dedicado actualizando cada 500ms
  - Mutex para acceso thread-safe
  - Historial circular de 60 muestras

Metricas GPU (via NVML):
  - nvmlDeviceGetTemperature -> temperatura actual
  - nvmlDeviceGetPowerUsage -> consumo watts
  - nvmlDeviceGetUtilizationRates -> % utilizacion
  - nvmlDeviceGetMemoryInfo -> VRAM usado/libre

Metricas RAM:
  - Lee /proc/meminfo en cada tick
  - Total, usado, disponible

Metricas CPU:
  - Lee /proc/stat
  - Calcula % utilizacion entre ticks

Snapshot (telemetry_snapshot_t):
  - gpu_temp_c, gpu_power_w, gpu_util_pct
  - vram_used_mb, vram_total_mb
  - ram_used_mb, ram_total_mb, ram_available_mb
  - cpu_util_pct
  - uptime_ms
  - gpu_healthy, thermal_throttle
  - engine_running, tokens_per_sec (via IPC)
  - spillover_active, predictive_armed (via IPC)

------------------------------------------------------------------------------
3.4 IPC BUS (INTER-PROCESS COMMUNICATION)
------------------------------------------------------------------------------
Estado: IMPLEMENTADO Y FUNCIONAL (100% REAL)

Ubicacion: /dev/shm/hexos_state (POSIX shared memory)

Estructura compartida (hexos_shared_state_t):
  Header:
    - magic: 0x4845584F ("HEXO")
    - version: 1
    - last_update_ns: timestamp nanosegundos

  HEXOS State:
    - hexos_running: bool
    - hexos_state: INIT/RUNNING/DEGRADED/etc
    - profile: BALANCED/LOW_VRAM/PERFORMANCE
    - modules_connected: bitmask

  Cognitive Kernel State:
    - running: bool
    - state: IDLE/RUNNING/ERROR
    - tokens_per_sec: float
    - queue_depth: uint32
    - active_ctx_id: uint32
    - total_tokens: uint64

  Memory Core State:
    - initialized: bool
    - spillover_active: bool
    - episodic_count: uint32
    - identity_hash: uint32
    - continuity_text[256]: mensaje CONTINUITY

  Resources:
    - vram_pressure: 0-100
    - ram_pressure: 0-100
    - thermal_state: OK/WARM/HOT/CRITICAL
    - vram_budget_model_mb
    - vram_budget_kv_mb
    - vram_budget_workspace_mb

  Predictive:
    - armed: bool
    - active: bool
    - predictions_queued: uint32
    - hit_rate: float 0.0-1.0

API:
  - hexos_ipc_init(): HEXOS crea shared memory
  - hexos_ipc_connect(): Modulos se conectan
  - hexos_ipc_shutdown(): Limpieza
  - hexos_ipc_update_cognitive(): Actualiza estado CK
  - hexos_ipc_update_memory(): Actualiza estado MC
  - hexos_ipc_update_predictive(): Actualiza predictive
  - hexos_ipc_module_connected(): Verifica conexion

Message Queue:
  - Definido en header (hexos_message_t)
  - Implementacion: PLACEHOLDER (no funcional aun)

8. INTEGRACION CON HELIOS
================================================================================

HEXOS es el componente base del stack HELIOS:

  +---------------------------------------------------+
  |                    HELIOS                         |
  |  +---------------------------------------------+  |
  |  |            Cognitive Kernel                 |  |
  |  |  (inferencia, generacion, razonamiento)    |  |
  |  +---------------------------------------------+  |
  |  +---------------------------------------------+  |
  |  |             Memory Core                     |  |
  |  |  (HNF-EXT, episodic, CONTINUITY)           |  |
  |  +---------------------------------------------+  |
  |  +---------------------------------------------+  |
  |  |           Predictive Memory                 |  |
  |  |  (prediccion, cache, prefetch)             |  |
  |  +---------------------------------------------+  |
  |                       |                           |
  |                   IPC Bus                         |
  |                       |                           |
  |  +---------------------------------------------+  |
  |  |                 HEXOS                       |  |
  |  |  (hardware, telemetry, resource mgmt)      |  |
  |  +---------------------------------------------+  |
  +---------------------------------------------------+
                          |
                      Hardware
              (GPU, RAM, CPU, Storage)

El Cognitive Kernel y Memory Core se conectan a HEXOS via IPC:
  1. HEXOS inicia y crea /dev/shm/hexos_state
  2. Modulos llaman hexos_ipc_connect()
  3. Modulos actualizan su estado en shared memory
  4. HEXOS lee estado para dashboard y monitoring
  5. HEXOS envia mensajes de control (shutdown, pause, etc)

10. NOTAS TECNICAS
================================================================================

- HEXOS corre 100% en CPU, no usa CUDA directamente
- La telemetria GPU usa NVML (libreria de management, no compute)
- El IPC usa POSIX shared memory (/dev/shm) - zero-copy
- El dashboard usa escape sequences ANSI estandar
- Compilado con -O2 para produccion, -g para debug
